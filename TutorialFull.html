Kotlin Programming Tutorial for Beginners

Полный курс для Windows + Android Studio · от установки до корутин
Введение
00 Обзор курса теория
Зачем: Понять, что такое Kotlin, где он применяется и какие предварительные знания нужны для прохождения курса.

Kotlin — статически типизированный язык программирования, работающий поверх JVM. Разработан JetBrains, официальный язык для Android-разработки. Также компилируется в JavaScript и нативный код.

Предварительные требования:

  • Базовое понимание программирования (переменные, циклы, условия)
  • Windows 10/11 (64-bit)
  • 8+ ГБ ОЗУ (для Android Studio)
  • Android Studio (включает JDK и Kotlin)

Почему Kotlin:

  • Краткий и выразительный синтаксис
  • Null safety на уровне типов
  • 100% совместимость с Java
  • Поддержка функционального программирования
  • Корутины для асинхронности
  • Официальный язык Android
💡 Для этого курса: Мы будем использовать Android Studio как основную IDE. Она бесплатна, включает JDK, Kotlin, Gradle и всё необходимое. Даже если вы не планируете делать Android-приложения, Android Studio — отличная среда для изучения Kotlin.

03 Data Types and Variables теория
Зачем: Освоить объявление переменных и основные типы данных Kotlin.
// val — неизменяемая (immutable), аналог final val name = "Alice" // name = "Bob" // Ошибка компиляции // var — изменяемая (mutable) var age = 25 age = 26 // Явное указание типа val pi: Double = 3.14 var count: Int = 10 // Основные типы val b: Byte = 127 // 8 бит: -128..127 val s: Short = 32767 // 16 бит val i: Int = 2_000_000 // 32 бита val l: Long = 9_000_000_000L // 64 бита val f: Float = 3.14F // 32 бита val d: Double = 3.14159 // 64 бита val bool: Boolean = true val ch: Char = 'A'
  • val — рекомендуется по умолчанию (безопасность).
  • var — только когда значение действительно меняется.
  • Подчёркивания в числах (2_000_000) улучшают читаемость.
  • Суффиксы: L (Long), F (Float).
04 String, Literals and String Interpolation теория
Зачем: Научиться работать со строками, шаблонами и многострочными литералами.
val name = "Kotlin" val version = 2.0 // Интерполяция println("Language: $name, version: $version") println("Length: ${name.length}") // Экранирование println("He said: \"Hello\"") println("Path: C:\\Users\\Alice") // Многострочная строка (raw string) val multiline = """ Line 1 Line 2 Line 3 """ println(multiline) // Полезные функции println(name.uppercase()) println(name.lowercase()) println(name.reversed()) println(name.substring(0, 3))
  • $varName — простая интерполяция.
  • ${выражение} — для выражений или при склейке с текстом.
  • """...""" — raw string: без экранирования, сохраняет переносы.
  • Строки неизменяемы — все операции возвращают новую строку.

// Однострочный комментарий /* Многострочный комментарий */ /** * KDoc-комментарий для документации * @param name имя пользователя * @return приветствие */ fun greet(name: String): String = "Hello, $name"

06 Constants, Variables and Data Types теория
Зачем: Различать val, const val и var, понимать преобразования типов.
// const val — compile-time константа (только top-level или в object) const val MAX_USERS = 100 // val — runtime-неизменяемая val currentTime = System.currentTimeMillis() // var — изменяемая var counter = 0 // Явные преобразования (нет неявных!) val intVal: Int = 42 val longVal: Long = intVal.toLong() val doubleVal: Double = intVal.toDouble() val stringVal: String = intVal.toString() val parsed: Int = "123".toInt()
  • const val — известна на этапе компиляции, эффективнее.
  • Kotlin не делает неявных преобразований между числами.
  • Всегда используйте toInt(), toLong(), toDouble() и т.д.
  • toIntOrNull() — безопасный парсинг, вернёт null при ошибке.
Управление потоком
07 IF ELSE теория
Зачем: Ветвление логики выполнения программы.
val score = 85 if (score >= 90) { println("Отлично") } else if (score >= 75) { println("Хорошо") } else if (score >= 60) { println("Удовлетворительно") } else { println("Не сдано") } // Вложенные условия val hasTicket = true val age = 20 if (hasTicket) { if (age >= 18) { println("Доступ разрешён") } }
  • Условие всегда типа Boolean (не Int, как в C).
  • Фигурные скобки необязательны для одной строки, но рекомендуются.
  • else if — последовательная проверка условий.
08 IF Expressions теория
Зачем: В Kotlin if — это выражение, возвращающее значение. Это заменяет тернарный оператор.
// if как выражение val a = 10 val b = 20 val max = if (a > b) a else b println("Max: $max") // 20 // Многострочный вариант val result = if (a > b) { println("a больше") a } else { println("b больше") b } // В тернарном стиле (нет оператора ?: как в Java) val status = if (a % 2 == 0) "even" else "odd"
  • Последнее выражение в блоке — возвращаемое значение.
  • Заменяет тернарный оператор ? : из Java/C.
  • Тип результата выводится автоматически.
💡 Совет: Если обе ветки возвращают один тип — используйте if как выражение. Это идиоматично для Kotlin.
09 WHEN Expressions теория
Зачем: Мощная замена switch с поддержкой диапазонов, типов и условий.
val day = 3 // when с константами val dayName = when (day) { 1 -> "Понедельник" 2 -> "Вторник" 3 -> "Среда" 4, 5 -> "Четверг или Пятница" 6, 7 -> "Выходной" else -> "Неизвестно" } println(dayName) // when с диапазонами val grade = when (score) { in 90..100 -> "A" in 80..89 -> "B" in 70..79 -> "C" else -> "F" } // when без аргумента (замена if-else цепочки) val x = 15 when { x < 0 -> println("Отрицательное") x == 0 -> println("Ноль") x > 0 -> println("Положительное") } // when с типами fun describe(value: Any): String = when (value) { is String -> "Строка длиной ${value.length}" is Int -> "Целое число" is List<*> -> "Список из ${value.size} элементов" else -> "Неизвестный тип" }
  • when может быть выражением (возвращает значение) или инструкцией.
  • Поддерживает: константы, диапазоны (in), типы (is), условия без аргумента.
  • else обязателен, если when используется как выражение и не все случаи покрыты.
  • Запятая объединяет несколько значений в одну ветку.
Циклы и итераторы
10 What are Iterators? теория
Зачем: Понять, что такое итератор и как он связан с циклами.

Итератор — объект, позволяющий последовательно перебирать элементы коллекции. В Kotlin любая коллекция реализует интерфейс Iterable<T>, который предоставляет метод iterator().

val list = listOf("a", "b", "c") // Явное использование итератора val iterator = list.iterator() while (iterator.hasNext()) { println(iterator.next()) } // Неявно — через for for (item in list) { println(item) }
  • hasNext() — есть ли следующий элемент.
  • next() — вернуть следующий элемент и сдвинуть указатель.
  • for — синтаксический сахар над итератором.
  • Итераторы реализуют Iterable, Sequence и другие.
11 FOR Loop and how it works теория
Зачем: Основной цикл для перебора коллекций и диапазонов.
// По коллекции val fruits = listOf("apple", "banana", "cherry") for (fruit in fruits) { println(fruit) } // По индексам for (i in fruits.indices) { println("$i: ${fruits[i]}") } // С индексом и значением for ((index, value) in fruits.withIndex()) { println("$index -> $value") } // Диапазоны for (i in 1..5) print("$i ") // 1 2 3 4 5 for (i in 1 until 5) print("$i ") // 1 2 3 4 for (i in 5 downTo 1) print("$i ") // 5 4 3 2 1 for (i in 1..10 step 2) print("$i ") // 1 3 5 7 9 // По Map val map = mapOf("a" to 1, "b" to 2) for ((key, value) in map) { println("$key = $value") }
  • in — ключевое слово для итерации.
  • .. — включающий диапазон; until — не включая правый конец.
  • downTo — обратный порядок; step — шаг.
  • withIndex() — пары (index, value).
12 WHILE Loop теория
Зачем: Цикл с предусловием — выполняется, пока условие истинно.
var count = 0 while (count < 5) { println("Count: $count") count++ } // Чтение ввода до пустой строки var input: String? while (true) { input = readLine() if (input.isNullOrEmpty()) break println("Вы ввели: $input") }
  • Условие проверяется перед каждой итерацией.
  • Если условие изначально false — тело не выполнится ни разу.
  • while (true) — бесконечный цикл, выход через break.
13 DO WHILE Loop теория
Зачем: Цикл с постусловием — тело выполняется минимум один раз.
var attempt = 0 do { println("Попытка ${attempt + 1}") attempt++ } while (attempt < 3) // Разница с while: тело выполнится хотя бы раз var x = 10 do { println("Выполнится один раз, x = $x") } while (x < 5) // условие ложно, но тело уже выполнено
  • Тело выполняется до проверки условия.
  • Используется, когда нужно гарантированно выполнить действие хотя бы раз.
  • Типичные сценарии: меню, запрос пароля, retry-логика.
14 BREAK statements и CONTINUE keyword теория
Зачем: Управлять поведением циклов — прерывать или пропускать итерации.
// BREAK — выход из цикла for (i in 1..10) { if (i == 5) break print("$i ") // 1 2 3 4 } // CONTINUE — пропуск итерации for (i in 1..5) { if (i == 3) continue print("$i ") // 1 2 4 5 } // В while var n = 0 while (n < 10) { n++ if (n % 2 == 0) continue // пропустить чётные println("Нечётное: $n") }
  • break — немедленный выход из ближайшего цикла.
  • continue — переход к следующей итерации.
  • Оба работают в for, while, do-while.
15 Labelled FOR Loop продвинутое
Зачем: Управлять вложенными циклами — break/continue для внешнего цикла.
// Метка на внешнем цикле outer@ for (i in 1..3) { for (j in 1..3) { if (i == 2 && j == 2) { break@outer // выход из ВНЕШНЕГО цикла } println("i=$i, j=$j") } } // continue с меткой loop@ for (i in 1..3) { for (j in 1..3) { if (j == 2) continue@loop // продолжить внешний цикл println("i=$i, j=$j") } } // Метка на лямбде listOf(1, 2, 3).forEach label@{ num -> if (num == 2) return@label println(num) }
  • Метка: имя@ перед циклом.
  • break@имя — выход из помеченного цикла.
  • continue@имя — переход к следующей итерации помеченного цикла.
  • Также работает с return@метка в лямбдах.
Функции и интероперабельность
16 Declaring functions теория
Зачем: Освоить синтаксис объявления функций, параметры и возвращаемые значения.
// Простая функция fun greet(name: String): String { return "Hello, $name!" } // Функция с одним выражением (expression body) fun square(x: Int): Int = x * x // Тип возвращаемого значения выводится автоматически fun add(a: Int, b: Int) = a + b // Unit — аналог void fun printMessage(msg: String) { println(msg) } // Функция с локальной функцией внутри fun outer() { fun inner() = println("Inner") inner() }
  • Синтаксис: fun имя(параметры): ТипВозврата { тело }.
  • Unit — если функция ничего не возвращает (можно опустить).
  • Expression body: fun f() = выражение — без return и скобок.
  • Функции могут быть вложенными (local functions).
17 Interoperability with Java code теория
Зачем: Kotlin на 100% совместим с Java — можно вызывать Java-код из Kotlin и наоборот.
// Вызов Java-класса из Kotlin import java.util.ArrayList fun main() { val list = ArrayList<String>() list.add("one") list.add("two") for (item in list) { println(item) } } // Java-аннотации для совместимости @JvmStatic fun staticMethod() { } @JvmOverloads fun greet(name: String = "World") { } @JvmField val CONSTANT = 42 // Из Java: HelloWorldKt.main()
  • Kotlin-файл File.kt компилируется в класс FileKt.
  • @JvmName — переименовать сгенерированный класс.
  • @JvmStatic — сделать метод статическим для Java.
  • @JvmOverloads — генерировать перегрузки для default-параметров.
  • Java-код можно вызывать напрямую, без обёрток.
18 Function as Expressions теория
Зачем: Понять, что функция — это значение, которое можно присвоить переменной и передать.

22 Tailrec Functions продвинутое
Зачем: Оптимизация хвостовой рекурсии — избежать переполнения стека.
// Обычная рекурсия — риск StackOverflow fun factorial(n: Int): Long { if (n <= 1) return 1 return n * factorial(n - 1) // не хвостовой вызов } // Хвостовая рекурсия с tailrec tailrec fun factorialTail(n: Int, acc: Long = 1): Long { if (n <= 1) return acc return factorialTail(n - 1, acc * n) // хвостовой вызов } // Сумма чисел от 1 до n tailrec fun sum(n: Int, acc: Int = 0): Int = if (n == 0) acc else sum(n - 1, acc + n) fun main() { println(factorialTail(20)) // 2432902008176640000 println(sum(100000)) // без переполнения стека }
  • tailrec — компилятор преобразует рекурсию в цикл.
  • Условие: рекурсивный вызов должен быть последней операцией.
  • Используйте аккумулятор для накопления результата.
  • Без tailrec глубокая рекурсия → StackOverflowError.

35 Sealed class продвинутое
Зачем: Ограниченная иерархия — идеально для представления состояний и результатов.
// Sealed class — все наследники известны компилятору sealed class Result<out T> { data class Success<T>(val data: T) : Result<T>() data class Error(val message: String, val code: Int) : Result<Nothing>() object Loading : Result<Nothing>() } // Sealed interface sealed interface UiState { object Loading : UiState data class Success(val items: List<String>) : UiState data class Error(val msg: String) : UiState } fun <T> handleResult(result: Result<T>): String = when (result) { is Result.Success -> "Успех: ${result.data}" is Result.Error -> "Ошибка ${result.code}: ${result.message}" Result.Loading -> "Загрузка..." // else не нужен — все случаи покрыты } fun render(state: UiState): String = when (state) { UiState.Loading -> "⏳" is UiState.Success -> "✅ ${state.items.size} элементов" is UiState.Error -> "❌ ${state.msg}" } fun main() { println(handleResult(Result.Success(42))) println(handleResult(Result.Error("Not found", 404))) println(handleResult(Result.Loading)) }

  • Компилятор знает все варианты → when без else.

  • sealed interface (Kotlin 1.5+) — альтернатива с большей гибкостью.

38 Higher-Order Functions теория

Зачем: Безопасно работать с nullable-значениями.

52 Elvis теория
Зачем: Задать значение по умолчанию для nullable.
val name: String? = null // Elvis — значение справа если слева null val displayName = name ?: "Гость" println(displayName) // Гость // С safe call val length = name?.length ?: 0 println(length) // 0 // Elvis с throw val required: String = name ?: throw IllegalArgumentException("Name required") // Elvis с return fun process(input: String?) { val value = input ?: return println(value) } // Elvis с блоком val result = name ?: run { println("Вычисляем значение по умолчанию") "Default" } // Цепочка data class Config(val host: String?, val port: Int?) val config: Config? = null val host = config?.host ?: "localhost" val port = config?.port ?: 8080 // В функциях fun greet(name: String?) = "Hello, ${name ?: "Guest"}!"

53 Lateinit keyword продвинутое
Зачем: Отложить инициализацию non-null свойства.
class UserService { // lateinit — обещаем инициализировать позже lateinit var repository: UserRepository lateinit var logger: Logger fun init(repo: UserRepository, log: Logger) { repository = repo logger = log } fun findUser(id: Int) { if (::repository.isInitialized) { logger.log("Finding user $id") repository.find(id) } } } // Ограничения lateinit: // - только var (не val) // - только non-null тип // - не для примитивов (Int, Boolean и т.д.) // - не в primary constructor // Проверка инициализации class Example { lateinit var name: String fun check() { if (::name.isInitialized) { println(name) } else { println("Не инициализировано") } } } // Для примитивов — Lateinit не работает, нужен nullable или делегат class Counter { var count: Int = 0 // default // lateinit var count: Int // ошибка }

  • Для DI, тестов, Android (views, adapters).
54 Lazy delegation и 'lateinit' vs. 'lazy' продвинутое
Зачем: Инициализировать значение при первом обращении.

  • Только для val.
  • Thread-safe по умолчанию (SYNCHRONIZED).
  • lateinit — для var, инициализация вручную.
  • lazy — для тяжёлых вычислений, DI, singleton.

60 Что такое Coroutines? Связь с Threads теория
Зачем: Понять модель асинхронности Kotlin.

Coroutine — лёгкий поток выполнения, который можно приостановить и возобновить. В отличие от потоков ОС, корутины:

  • Не привязаны к потоку ОС — могут выполняться на пуле потоков.
  • Очень дешёвые: тысячи корутин на одном потоке.
  • Приостановка (suspend) не блокирует поток.
  • Структурированная конкурентность — родитель ждёт детей.

Ключевые понятия:

  • suspend fun — функция, которую можно приостановить.
  • CoroutineScope — область жизни корутин.
  • Dispatchers — определяют, на каком потоке выполняется.
  • Job — управление жизненным циклом.

Подключение в Android Studio:

// В app/build.gradle.kts (Android) dependencies { implementation("org.jetbrains.kotlinx:kotlinx-coroutines-android:1.9.0") } // В Kotlin/JVM проекте dependencies { implementation("org.jetbrains.kotlinx:kotlinx-coroutines-core:1.9.0") }

61 launch, async, runBlocking теория
Зачем: Основные билдеры корутин.
import kotlinx.coroutines.* fun main() = runBlocking { // launch — «запустить и забыть», возвращает Job val job = launch { delay(1000) println("Из launch") } job.join() // ждём завершения // async — возвращает Deferred (с результатом) val deferred: Deferred<Int> = async { delay(1000) 42 } val result = deferred.await() println("Результат: $result") // Несколько async параллельно val a = async { fetchData(1) } val b = async { fetchData(2) } println("${a.await()} + ${b.await()}") } suspend fun fetchData(id: Int): Int { delay(500) return id * 10 }
  • runBlocking — блокирует поток до завершения (для main, тестов).
  • launch — fire-and-forget, возвращает Job.
  • async — возвращает Deferred<T>, результат через await().
  • delay() — suspend-функция, не блокирует поток.
62 withContext, withTimeoutOrNull теория
Зачем: Переключать контекст и ограничивать время выполнения.
import kotlinx.coroutines.* fun main() = runBlocking { // withContext — переключение контекста val result = withContext(Dispatchers.IO) { // тяжёлая операция ввода-вывода delay(1000) "Data loaded" } println(result) // withTimeout — бросает TimeoutCancellationException try { withTimeout(500) { delay(1000) println("Не выполнится") } } catch (e: TimeoutCancellationException) { println("Таймаут!") } // withTimeoutOrNull — возвращает null вместо исключения val res = withTimeoutOrNull(500) { delay(1000) "Done" } println(res) // null }
  • withContext — переключение на другой диспетчер, возвращает результат.
  • withTimeout — отмена по таймауту с исключением.
  • withTimeoutOrNull — отмена с null.
  • Оба — suspend-функции.
63 Suspending function теория
Зачем: Создавать функции, которые можно приостанавливать.
import kotlinx.coroutines.* // suspend — можно вызывать только из корутины или другой suspend-функции suspend fun fetchUser(id: Int): String { delay(1000) // приостановка, не блокировка return "User$id" } suspend fun fetchAll(ids: List<Int>): List<String> { return ids.map { fetchUser(it) } // последовательно } fun main() = runBlocking { println(fetchUser(1)) println(fetchAll(listOf(1, 2, 3))) } // suspend можно вызывать из: // - другой suspend-функции // - корутинного билдера (launch, async, runBlocking) // НЕЛЬЗЯ из обычной функции
  • suspend — маркер, что функция может приостанавливаться.
  • Приостановка не блокирует поток.
  • Компилятор преобразует в state machine.
  • Вызывается только из корутинного контекста.
64 Cancellation and Timeouts теория
Зачем: Отменять корутины и обрабатывать таймауты.
import kotlinx.coroutines.* fun main() = runBlocking { // Отмена Job val job = launch { repeat(1000) { i -> delay(100) println("Итерация $i") } } delay(350) job.cancel() job.join() // ждём завершения отмены // cancelAndJoin val job2 = launch { try { delay(10000) } finally { println("Очистка ресурсов") } } delay(100) job2.cancelAndJoin() // Таймаут val result = withTimeoutOrNull(1000) { repeat(100) { delay(100) println("Работа $it") } "Готово" } println(result) // null (таймаут) // Проверка статуса val job3 = launch { delay(1000) } println(job3.isActive) // true println(job3.isCancelled) // false job3.cancel() println(job3.isCancelled) // true }
  • cancel() — запрос на отмену (кооперативный).
  • cancelAndJoin() — отмена + ожидание.
  • finally — для очистки ресурсов.
  • Отмена работает только в suspend-точках.
65 Cooperative suspending functions and isActive продвинутое
Зачем: Делать длительные операции отменяемыми.
import kotlinx.coroutines.* // НЕ отменяемая — блокирует suspend fun badLoop() { var i = 0 while (true) { // тяжёлая работа без suspend-точек i++ if (i % 1_000_000 == 0) println(i) } } // Кооперативная — проверяет isActive suspend fun goodLoop() { var i = 0 while (currentCoroutineContext().isActive) { i++ if (i % 1_000_000 == 0) println(i) // или: yield() — передать управление } println("Отменено на $i") } // С ensureActive suspend fun processItems(items: List<String>) { for (item in items) { ensureActive() // бросает CancellationException если отменено process(item) } } fun process(item: String) { /* ... */ } fun main() = runBlocking { val job = launch { goodLoop() } delay(100) job.cancelAndJoin() }
  • Отмена в Kotlin кооперативная.
  • isActive — проверка статуса корутины.
  • ensureActive() — бросить исключение если отменено.
  • yield() — передать управление, точка отмены.
  • Все suspend-функции из stdlib — кооперативные.
66 Exception Handling in Coroutines теория
Зачем: Правильно обрабатывать ошибки в корутинах.
import kotlinx.coroutines.* fun main() = runBlocking { // try/catch внутри корутины val job1 = launch { try { throw RuntimeException("Ошибка") } catch (e: Exception) { println("Поймано: ${e.message}") } } job1.join() // CoroutineExceptionHandler val handler = CoroutineExceptionHandler { _, e -> println("Глобально поймано: ${e.message}") } val job2 = launch(handler) { throw RuntimeException("Критическая ошибка") } job2.join() // async — исключение в await() val deferred = async { throw RuntimeException("Async error") } try { deferred.await() } catch (e: Exception) { println("Async: ${e.message}") } // supervisorScope — изоляция ошибок supervisorScope { val child1 = launch { delay(100) throw RuntimeException("Child1 failed") } val child2 = launch { delay(200) println("Child2 работает независимо") } child1.join() child2.join() } }
  • launch — исключение «всплывает» к родителю.
  • async — исключение хранится, бросается в await().
  • CoroutineExceptionHandler — глобальный обработчик.
  • supervisorScope — ошибка ребёнка не отменяет siblings.
67 Sequential execution of suspending function теория
Зачем: Выполнять suspend-функции последовательно.
import kotlinx.coroutines.* import kotlin.system.measureTimeMillis suspend fun fetch(id: Int): Int { delay(1000) return id * 10 } fun main() = runBlocking { // Последовательно — 3 секунды val time1 = measureTimeMillis { val a = fetch(1) val b = fetch(2) val c = fetch(3) println("$a, $b, $c") } println("Последовательно: $time1 ms") // ~3000 // Параллельно через async — 1 секунда val time2 = measureTimeMillis { val a = async { fetch(1) } val b = async { fetch(2) } val c = async { fetch(3) } println("${a.await()}, ${b.await()}, ${c.await()}") } println("Параллельно: $time2 ms") // ~1000 }
  • Обычный вызов suspend — последовательно.
  • async + await() — параллельно.
  • measureTimeMillis — замер времени.
  • Порядок await() не влияет на параллельность.
68 Concurrency within Coroutine теория
Зачем: Запускать несколько корутин конкурентно.
import kotlinx.coroutines.* import kotlin.system.measureTimeMillis suspend fun loadData(id: Int): String { delay(1000) return "Data$id" } fun main() = runBlocking { // Конкурентно через async val time = measureTimeMillis { val deferreds = (1..5).map { id -> async(Dispatchers.IO) { loadData(id) } } val results = deferreds.awaitAll() println(results) } println("Время: $time ms") // ~1000 // launch + join val jobs = (1..3).map { id -> launch { println("Загружен $id") } } jobs.forEach { it.join() } // Ограничение конкурентности через Semaphore val semaphore = Semaphore(2) (1..5).map { id -> async { semaphore.withPermit { println("Обработка $id") delay(500) } } }.awaitAll() }
  • async + awaitAll() — параллельный запуск.
  • launch + join() — без результата.
  • Semaphore — ограничение параллелизма.
  • Все корутины внутри runBlocking — дети scope.
69 lazy 'async' продвинутое
Зачем: Запускать async только при первом await.
import kotlinx.coroutines.* fun main() = runBlocking { // Обычный async — стартует сразу val eager = async { println("Eager: старт") delay(1000) "Eager result" } println("Между async и await") println(eager.await()) // lazy async — стартует при await val lazy = async(start = CoroutineStart.LAZY) { println("Lazy: старт") delay(1000) "Lazy result" } println("Между async и await (lazy ещё не стартовал)") println(lazy.await()) // Ручной старт val manual = async(start = CoroutineStart.LAZY) { delay(500) "Manual" } manual.start() // запуск вручную println(manual.await()) // isActive для lazy val check = async(start = CoroutineStart.LAZY) { delay(100) } println(check.isActive) // false (ещё не стартовал) check.start() println(check.isActive) // true }
  • CoroutineStart.LAZY — не запускать до await()/start().
  • Полезно для условного запуска.
  • Экономит ресурсы, если результат не нужен.
  • Можно комбинировать с invokeOnCompletion.
70 CoroutineScope and CoroutineContext теория
Зачем: Управлять жизненным циклом и контекстом корутин.
import kotlinx.coroutines.* // CoroutineScope — управляет жизненным циклом class MyViewModel : CoroutineScope { private val job = Job() override val coroutineContext: CoroutineContext get() = job + Dispatchers.Main fun loadData() { launch { // корутина в scope } } fun onDestroy() { job.cancel() // отменить все корутины } } // coroutineScope — структурированная конкурентность suspend fun loadAll(): List<String> = coroutineScope { val a = async { fetch(1) } val b = async { fetch(2) } listOf(a.await(), b.await()) } suspend fun fetch(id: Int): String { delay(500) return "Item$id" } // CoroutineContext — набор элементов fun main() = runBlocking { val ctx = coroutineContext println(ctx[Job]) // Job println(ctx[CoroutineName]) // null (или имя) // Комбинирование контекстов val customCtx = ctx + CoroutineName("MyCoroutine") + Dispatchers.IO launch(customCtx) { println("Имя: ${coroutineContext[CoroutineName]?.name}") }.join() // SupervisorJob val supervisor = SupervisorJob() val scope = CoroutineScope(supervisor + Dispatchers.Default) scope.launch { throw RuntimeException() } scope.launch { println("Продолжает работать") } delay(100) scope.cancel() }
  • CoroutineScope — держит CoroutineContext.
  • CoroutineContext — Job, Dispatcher, Name, ExceptionHandler.
  • coroutineScope — создаёт дочерний scope, ждёт всех.
  • SupervisorJob — ошибка ребёнка не отменяет siblings.
  • Структурированная конкурентность: родитель ждёт детей.
71 Dispatchers: Confined, Default, Unconfined теория
Зачем: Управлять, на каком потоке выполняются корутины.
import kotlinx.coroutines.* fun main() = runBlocking { // Default — CPU-интенсивные задачи launch(Dispatchers.Default) { println("Default: ${Thread.currentThread().name}") // сложные вычисления }.join() // IO — ввод-вывод (сеть, файлы, БД) launch(Dispatchers.IO) { println("IO: ${Thread.currentThread().name}") // чтение файла, HTTP-запрос }.join() // Unconfined — без привязки к потоку launch(Dispatchers.Unconfined) { println("Unconfined до delay: ${Thread.currentThread().name}") delay(100) println("Unconfined после delay: ${Thread.currentThread().name}") }.join() // Main — UI-поток (Android, JavaFX) // launch(Dispatchers.Main) { ... } // Confined — свой пул потоков val confined = newSingleThreadContext("MyThread") launch(confined) { println("Confined: ${Thread.currentThread().name}") }.join() confined.close() // освободить ресурсы // Переключение внутри корутины launch { println("Старт: ${Thread.currentThread().name}") withContext(Dispatchers.IO) { println("IO: ${Thread.currentThread().name}") } println("Обратно: ${Thread.currentThread().name}") }.join() }
  • Dispatchers.Default — CPU-задачи, пул = кол-во ядер.
  • Dispatchers.IO — I/O-задачи, до 64 потоков.
  • Dispatchers.Main — UI-поток (Android, JavaFX).
  • Dispatchers.Unconfined — без привязки (осторожно).
  • withContext — переключение внутри корутины.
💡 В Android: Dispatchers.Main — главный UI-поток. Все обновления интерфейса должны быть на нём. Тяжёлые операции (сеть, БД) — на Dispatchers.IO.
